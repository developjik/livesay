What does a streamed answer do to a screen reader?

What this page does instead

  • The answer text is not a live region; it is aria-busy="true" while it streams.
  • The first two sentences are announced once, 600ms apart, through ariaNotify() when the browser has it and a hidden polite region when it does not. After that the page stays quiet — speech cannot keep up with tokens.
  • Tool status is a single polite message, then silence.
  • The end of the stream is announced: “Answer complete. 88 words.”
  • An error is announced once, assertively, then stops.

Audit it with a speech budget:

npx livesay audit http://127.0.0.1:4319/good.html --budget "announcements<8,no-partial,no-duplicate,no-silent"
